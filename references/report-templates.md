# 交付模板

三件交付物：**情报报告**（完整）、**一页简报**（投递用正文）、**附录**（评级与台账）。命名规则：`osint-<YYYYMMDD>-<主题缩写>.md`。

---

## 一、一页简报（邮件正文）

长度上限：手机一屏半。超过就不是简报，是报告。

```markdown

**期号** OSINT-<YYYYMMDD>-<NN> ｜ **窗口** <起>—<止> ｜ **密级** 内部 ｜ **编制** <日期时间>

## 一、核心判断（BLUF）
<一句话。必须包含：发生了什么、意味着什么、判断的概率与置信度。>
> 例：某国产能受限**极可能**（中置信度）延续至下季度，若 <指标> 未回落，则 <后果> 概率上升。

## 二、三条要闻
1. **<标题，≤15字>** —— <事实，≤60字>（A1／独立源 2）
   影响：<对委托方决策的具体含义，一句话>
2. **<标题>** —— <事实>（B2／独立源 1）

- 【评估】<判断一>：**可能**（55–80%），<置信度>。依据：<2–3条，带评级>。
- 【评估】<判断二>：**大致对半**。依据：<…>。

## 四、预警指标（下期回填）
| 指标 | 当前 | 阈值 | 若触发则 |
|---|---|---|---|
| <可观测事项> | 未出现 | <明确阈值> | <判断变化> |

- [ ] <未证实事项>（当前 C3／单源）——需 <何种证据> 才能定级
```

## 三、事件台账字段（Excel 或 Markdown 表均可）

| 字段 | 说明 |
|---|---|
| ID | E-001 递增 |
| 事件时间（当地） | 精确到小时；不确定写"约"并注明依据 |
| UTC+8 | 换算值 |
| 地点 | 国家/一级行政区/具体点位；不可考写"未定位" |
| 行为体 | 主体 + 客体 |
| 事件描述 | 一句话，只写事实，不写评价 |
| 来源方 | 机构名 |
| 来源等级 | A–F |
| 信息评级 | 1–6 |
| 独立印证数 | 按核验手册判定表计算 |
| URL | 一手出处 |
| 发布日 / 抓取日 | 两个都要 |
| 关联 PIR | PIR-1 / PIR-2 |
| 核验手段 | 官方文件比对 / 地理定位 / … |
| 存疑点 | 无则写"无" |

## 五、邮件正文（HTML）要点

`scripts/build_briefing.py` 会把上述 Markdown 简报转成内联样式的 HTML。发送时注意：

- **主题行格式**：`[情报简报] <主题> · <YYYY-MM-DD> · <核心判断一句话>`
  主题行本身就是情报。收件人只看主题也应知道该不该马上打开。
- 正文用 HTML，报告全文（.md）作附件。
- 正文尾部固定加一行：`本期置信度分布：高 X 条／中 Y 条／低 Z 条；待核 N 项。`——让收件人一眼看出这份东西的硬度。
- 不把未核实内容放在正文上半部分。

## 六、措辞替换表（定稿前 grep 一遍）

| 禁用词 | 处理 |
|---|---|
| 据悉、有消息称、分析人士认为、业内人士 | 换成具名来源 + 评级，或删除 |
| 综合多家媒体报道、多方消息证实 | 列名 + 独立源计数 |
| 局势持续紧张、前景不明 | 指标 + 阈值 + 时间窗 |
| 不排除、有可能、或将、似乎 | 概率词 + 置信度 |
| 显著、大幅、严重（无基准） | 数字 + 对比基期 |
| 普遍认为、众所周知 | 删除或给证据 |

**定稿自检**：把报告全文搜一遍上表词，命中即改。这一步能消掉八成"看起来像情报其实不是"的文本。
